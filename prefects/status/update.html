Duty replies

Contacts (who the bot can message)

The opt-in list behind reminders and notices. Name must match the roster exactly — that's how a duty row finds the number. Phone needs the country code (e.g. +85291234567). Only tick “opted in” once the prefect has actually agreed to receive WhatsApp reminders; unticked contacts are never messaged. Saving replaces the whole list.

"Send intro" sends the prefect_intro welcome template once to each opted-in contact who hasn't had it — save first, then send. The period dates fill {{start}}/{{end}} and are remembered for next time.

Handbook check

Follows the intro at the start of a change. Starting a round asks every opted-in prefect to open the handbook and send back the 6-digit code shown on the code page — embed that page in the handbook itself. The code changes every 10 minutes, and starting a round makes every earlier code stop working.

A prefect who has the code can pass it to another — a Notion embed has no login, so this records that someone opened the page, not that each person read it.

Automatic clean-up
Automatically delete ended duties

Duty days that have finished are kept for a while so you can still look them up, then removed for good. Turn this off and the roster keeps everything until you delete it by hand.

Keep past duties for

0–90 days. A day is only ever removed after it has ended, so today’s duty is never touched. The default of 7 matches how long WhatsApp reply history is stored.

Notion sync

Keeps the duty roster and a Notion database in step, both ways. A day added or edited in either place wins if it was changed more recently. Only days from today onwards are synced — past duties are left alone in Notion, so the automatic clean-up above can never touch your records there.

Connection
Sync with Notion

Runs with the nightly and morning jobs, and whenever you press Sync now. Needs NOTION_TOKEN set on the server, and the database shared with that integration (••• → Connections).

Which column is which

Press Detect properties first — these fill with your database’s real columns, and the obvious match for each is picked automatically. Only the date is required.

The duty’s time is written into the Date column as part of the date, so 9 September at 7:45am is one value. The page title is generated as “9/9 Prefect Duty” and overwritten on every sync — renaming a row by hand will not stick.

Location, team and prefect names are not synced — the database has no columns for them, so they stay here in the hub and a sync never touches them.
